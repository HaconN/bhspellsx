## 4. หน้าตาปัจจุบัน — source คือค่าจริง

### กลีบหลักสามชั้น

กลีบเป็น mesh กว้าง ปลายเรียว มีความโค้งตามยาวและขอบยกขึ้นตามขวาง คล้ายกลีบถ้วย
มีการโค้งเฉไปด้านข้างเล็กน้อย ไม่ใช่แผ่นวงรีเรียวยาวแบบก่อน

| ชั้น | จำนวน | ความยาว | ความสูงปลายเหนือฐานกลีบ | หมุน (องศา/tick) | สี |
| --- | ---: | ---: | ---: | ---: | --- |
| นอก | 10 | 6.6 | 1.0 | +0.22 | ฟ้า → ขาวฟ้า |
| กลาง | 8 | 4.2 | 1.6 | -0.28 | ฟ้า → ขาวฟ้า |
| ในสุด/HEART | 6 | 2.3 | 1.85 | +0.36 | ทองเข้ม → ทองอ่อน |

- โคนกลีบห่างศูนย์กลาง 0.65 บล็อก ยกฐานจากพื้น 0.06 บล็อก
- 16 segments ตามยาว × 5 vertices ต่อหน้าตัด ทำให้มีความโค้งตามขวางจริง
- Width ratio 0.65; cup สูงสุด 0.38; โค้งตามยาวสูงสุด 0.45 บล็อก
- บานใน 12 ticks ด้วย ease-out cubic; scale 0.12 → 1 และมุมเริ่มสูงกว่ามุมปลายทาง 18°
- มุมปลายทางคำนวณจากความยาว, curve และความสูงปลาย ไม่ใช้มุมเดียวกับทุกชั้น
- Alpha หลัก 0.64 แล้วไล่ให้อ่อนลงแถวโคนและขอบ
- HEART palette: base `(1.0, 0.60, 0.10)` → tip `(1.0, 0.90, 0.45)`
- กลีบนอก/กลางและกลีบลอยยังใช้ palette ฟ้าเดิม การเลือก palette ทองเช็ค `mesh == HEART`

### ตรงกลาง

- **ไม่มีแผ่นทองและไม่มีเส้นเกสรแล้ว**
- ใช้ ribbon ลมสองสาย หมุนขึ้นรอบศูนย์กลาง ทรง helix ปลายและขอบค่อย ๆ จาง
- รัศมี 0.85 และพองเพิ่มได้ 0.3 บล็อก; สูง 1.8 บล็อก; 1.15 รอบต่อสาย
- 48 segments ต่อสาย, alpha 0.28, หมุน 2.2°/tick
- สีล่าสุด `(1.0, 0.78, 0.24)` เป็นทอง
- ประกายเป็น vanilla `minecraft:glow` จริง ไม่ใช่ ender particle และไม่ได้เปลี่ยนสี native glow เป็นทอง
- Glow เกิดใน client branch ของ `CrystalHydroDomeAoe.tick()` หนึ่งเม็ดทุก 3 ticks ต่อโดม
  (ประมาณ 6.7 เม็ด/วินาทีที่ 20 TPS) ไม่ส่ง packet particle จาก server
- Native glow อาจอยู่ต่อชั่วครู่ตาม lifetime ปกติของ particle หลังโดมหาย

### กลีบลอย 24 กลีบ

- เป็น mesh ที่ renderer วาด ไม่ใช่ entity/particle ใหม่ จึงไม่เพิ่มงาน gameplay หรือ packet
- ความยาว 0.38 บล็อก, 6 segments, ใช้ทรงกลีบเดียวกับดอกหลักแต่เล็กลง
- จุดยึดกลีบกระจายสูงประมาณ 0.8–8.8 บล็อก; ตัวกลีบจริงมีขนาดและการเอียงเพิ่มเติมจากจุดยึด
- วงจรลอย 120 ticks; หมุนรอบแกน -0.65°/tick พร้อมพลิกกลีบเบา ๆ
- กระจายมุมด้วย golden angle และเหลื่อม phase ความสูงตาม index ให้มีทั้งช่วงล่าง/กลาง/บนพร้อมกัน
- รัศมีที่ใช้ได้ ณ ความสูง `y` คือ `sqrt((RADIUS - 0.65)^2 - y^2)`
  จากนั้นคูณตัวกระจายรัศมี 0.20–0.95 จึงหุบวงด้านบนตามทรงโดม ไม่ทะลุผิว
- Fade ช่วง 12% แรกและท้ายของวงจร เพื่อซ่อนจังหวะย้ายจากด้านบนกลับด้านล่าง
- `DRIFT_COUNT=24` คือจำนวนที่วนวาด; บางกลีบอาจกำลัง fade จนแทบมองไม่เห็น ไม่ใช่ 24 กลีบทึบตลอดเวลา

### ลายพื้น

- วงเส้นฟ้ารัศมี 8.15 บล็อก, 128 segments, กว้าง 0.035, สูงจากฐานโดม 0.035 บล็อก
- เส้นโค้งตกแต่ง 6 เส้น วางรอบบริเวณรัศมี 7.15–7.70 บล็อก
- Pulse สีทองอ่อน 2 วงเหลื่อมกัน หดจากรัศมี 8.15 → 1.1 บล็อก
- วงจร pulse 48 ticks ต่อวง; alpha ขึ้นลงด้วย sine ให้รอยต่อวงจรไม่กระโดด
- เป็นระนาบที่ยึดตำแหน่งร่าย ไม่ใช่ decal ที่ตามพื้นต่างระดับ จึงอาจจมเนินหรือลอยเหนือหลุม

## 5. ลำดับ render และข้อควรระวัง

- ผิวโดม/ลายพื้นใช้ additive RenderType เดิม: emissive entity shader + `SRC_ALPHA/ONE`
- กลีบและลมใช้ `RenderType.entityTranslucentEmissive(WHITE_TEXTURE)` แบบ alpha blend
- Texture คือ `forge:textures/white.png`; สีมาจาก vertex ไม่ได้เพิ่มไฟล์ภาพ
- ใช้ `FULL_BRIGHT` และ `OverlayTexture.NO_OVERLAY`; รักษา shader/state ที่ผ่านปัญหาของ Oculus มาแล้ว
- ลำดับปัจจุบัน: ผิวโดม → ลายพื้น/pulse → กลีบหลักและกลีบลอย → ลมวน
- มี targeted `endBatch(type)` เมื่อ buffer เป็น `MultiBufferSource.BufferSource` เพื่อแยกลำดับแต่ละ pass
- การแยก translucent batches ไม่ใช่การเรียงความลึกที่สมบูรณ์ข้ามทุกวัตถุ ยังต้องดูมุมซ้อน/น้ำ/particle จริง
- **ไม่ใช้ additive shine ซ้ำบนกลีบทั้งดอกแล้ว** เพราะของเดิมสว่างขาวทับกันจนกลบทรงและสีทอง
- Mesh/indices/ring trigonometry ถูก cache; ไม่สร้าง mesh/array ใหม่ทุกเฟรมในส่วน VFX ที่เพิ่ม
- Native glow ยังสร้าง particle object ตามปกติใน client tick; อย่าอ้างว่าทั้ง renderer/game path ไม่มี allocation เลย
- ระยะตัดการวาด 64 บล็อกยังเหมือนเดิม

บทเรียนเก่าที่สำคัญ: shader `getRendertypeEntityTranslucentShader()` แบบไม่ emissive
เคยทำกลีบดำ เพราะใช้ร่วมกับ state ที่ปิด lightmap ขณะที่ shader ยังอ่าน lightmap
อย่าเปลี่ยน shader/state เพียงเพราะดูธรรมดากว่าโดยไม่ตรวจ compatibility กับ Oculus/Iris

## 7. การตรวจสอบที่ทำแล้ว / ยังไม่ได้ทำ

ทำแล้ว:

- `gradlew.bat build --console=plain` ผ่านหลังแก้ชุดล่าสุด
- Build มี warning flat-file dependencies และ Gradle deprecation เดิม ไม่ได้อัปเกรด dependencies
- Gradle รายงาน `test NO-SOURCE` จึงอย่าตีความ build ผ่านว่าเป็น automated gameplay test
- ตรวจรูปทรงรุ่นกลีบกว้างด้วยข้อมูล mesh จาก Java builder จริงและภาพฉายทางเรขาคณิต
  ภาพนี้ไม่ใช่ภาพ Minecraft และไม่ได้จำลอง shader/particle ของเกม
- ตรวจช่วงบาน: กลีบนอกไกลสุดประมาณ 7.189 บล็อก; ความสูงสูงสุดของสามชั้นประมาณ
  1.246 / 1.660 / 1.910 บล็อกตามลำดับ (รวม y-offset)
- ตรวจวงโคจร 24 กลีบล่าสุดเชิงตัวเลข: ขอบเขตแบบเผื่อขนาดกลีบไม่เกินประมาณ 9.746 บล็อกจากศูนย์กลาง
  อยู่ภายในโดมรัศมี 10; ทุกช่วงเวลาที่สุ่มตรวจมีตัวที่มองเห็นทั้งโซนล่าง/กลาง/บน
- ตรวจ SHA-256 ของ jar ต้นทางกับไฟล์ที่ลง Prism ตรงกัน
